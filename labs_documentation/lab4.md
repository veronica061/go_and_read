## Упрощенный Kanban и Iterative Development

### Обоснование выбора:
- **Малая команда.** Нет отдельного продакт овнера, менеджера, аналитика —> нет необходимости в сложном цикле, нет ресурсов на сложный цикл.
- **Гибкость.** Позволяет быстро менять приоритеты по ходу работы (сдачи этапов ЛР).
- **Фокус на результате.** Наибольшее количество времени отводится на написание кода.

### Детальное описание жизненного цикла

#### Фаза 0: Планирование работы.
**Цель:** определить требования к проекту и запустить простейшую работающую версию.
- Определение ТЗ и технических требований к проекту.
- Выбор стека технологий.
- Создание минимально рабочего прототипа.
- Создание доски задач и плана разработки.

#### Фаза 1: Итеративная разработка MVP (3-5 недель)
**Цель:** Быстро получить первый работающий прототип.

**Процесс (цикл):**
1. **Планирование недели и распределение задач**
2. **Разработка:**
   - Каждый берет задачу, отмечает "в процессе" и начинает работу.
   - Работа ведётся в отдельных ветках Git.
3. **Ревью кода:**
   - Подтянуть законченную задачу в ветку для тестирования.
   - Написать тесты для всех изменений.
   - Протестированный код pull request в main.
4. **Деплой:** Как только в main ветке накопилось что-то значимое, делать деплой на тестовый сервер.

#### Фаза 2: Доработка функций
**Цель:** Добавить ключевые функции, отсутствующие в прототипе, и улучшить пользовательский опыт.
- Повторение итеративного процесса из фазы 1.

#### Фаза 3: Поддержка и эволюция (постоянно)
**Цель:** Поддерживать работающий сайт, исправлять баги и добавлять новые функции по мере поступления идей.
